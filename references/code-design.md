# XPOST 代码设计约定 · 产物部署与实验

适用于 XPOST 的 Agent、串口、板端 runtime 和实验 runner。可将本页作为项目设计文档起点。随实现校正符号和路径，在现有项目说明中引用一份正文。

1. **一个职责有一个所有者。** libbpf-mcu 生成并发布容器。Agent 选择 release、验证原始字节、按目标固件准备镜像。xpost-elf 解释已有 Compact ELF 和 XPM1 约定。xpost-serial 管理传输、设备身份复核与写入。板端预装和切换活动入口。xpost-test 组织实验、入库和分析。HTTP、MCP 与实验入口调用同一操作实现。
2. **标识按对象使用。** 固件 profile、XDP 调用名、生产程序名、执行模式和槽位各自表达一个事实。上游文件名和索引归上游所有。把必要映射集中在 Agent 一处。HAL 没有部署容器；rBPF 使用已处理 map 引用的 eBPF。AOT/JIT 的原生定位逻辑只用于原生镜像。
3. **一次验证对应一组确切字节。** 区分发布文件摘要和定址后装载字节摘要。将派生镜像绑定到原容器、固件摘要、模式、槽位布局和 helper。保留原件，先准备再发布缓存，失败或重试时避免读到半成品。检查完成后传递同一份已验证字节，禁止按路径重开未验证文件或跨固件借用缓存。
4. **设备操作有明确边界。** 全批预检后才擦写；独立冷安装每次尝试都重新核对设备身份。预装完成且校验成功才发布入口，失败继续运行当前槽。分别计数固件烧录、冷安装、SRAM 预装和入口切换。速率点、重复采样、读指标和绘图不得触发重烧。
5. **迁移按调用链结束。** 先接正常入口与全部合法调用方，再删旧实现、依赖、配置、别名回退和已失效的文档指引。保留有独立职责的共享代码和历史数据。复核配置分派、错误分支和重试；仓库中每一处设备写入都应能追溯到显式操作。
6. **让实验流程可以从源码审核。** 模块顶部沿用 //! 伪代码，写明烧录所属循环层级、负载、触发、窗口终点和指标分母。设备与主机分别使用各自时钟。失败、不可归属与零样本可区分；结果按 run_id 追到输入、镜像和查询。PR 明确区分主机对照、板上观测与估算值。
