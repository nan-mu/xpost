## Disposable PostgreSQL 18

The tests used a fresh database named `reconcile_fixture` and a synthetic writer.
The writer owned `release` and lacked database-level CREATE.
The fixture copied the observed default table ACL for both read-only roles.
Using a different database name also checked that preparation follows the configured database.

- `cargo test` passed 38 regular tests. The default release build and rustfmt passed.
- `reconciles_tables_and_protects_active_collection` used the production preparation and resume interfaces.
  It checked creation of 132 tables and one winner in concurrent preparation.
  It removed one table in the fixture and checked that preparation restored it.
- The same test checked column name, type modifier, order, and nullability mismatches.
  The selected table changed OID and lost its old row.
  A compatible table kept its OID and marker. An unmanaged table kept its marker.
- The test exercised missing and mismatched tables through read-only check or resume.
  The mismatched table remained intact after read-only validation failed.
- A retained firewall config referenced an artifact slated for rebuild.
  FK restoration failed. Transaction rollback preserved both rows and the validated constraint.
  An unmanaged dependent view also blocked the rebuild.
- Two live connections shared schema protection. A second prepare refused to proceed.
  A duplicate campaign lock failed. Forced guard loss stopped protected work.
  An open writer kept its own shared lock until it closed.
- `recovers_an_interrupted_network_write_and_keeps_its_artifacts` killed the writer connection.
  The existing campaign guard stayed connected. Recovery reconnected and finalized the same attempt.
  When preparation rebuilt the Metrics snapshot table, a valid retained row kept its NULL references.
  Both restored foreign keys were validated.
- EXB2 passed in all four modes. Case kept raw bytes, media type, metadata, digest, and run links.
  The campaign fixture passed analysis replacement and rollback checks.
- `medium_run.sql` passed as `experiment_ro` for Case Trace, four EXB2 modes, and firewall Metrics.
  The read-only role could SELECT new tables. An actual INSERT into `bench_artifact` was denied.
  The backup role also received SELECT through the default ACL.
