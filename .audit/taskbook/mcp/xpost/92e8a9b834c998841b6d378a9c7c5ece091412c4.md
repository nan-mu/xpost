## Lifecycle and ownership

`python3 xpost-agent/tests/lifecycle.py <fixture-a> <fixture-b>` ran real
processes and HTTP on a Mac. The baseline binary failed at `start`. Both
new fixture builds used `--features test-device`. Build B also used
`CARGO_PROFILE_DEV_DEBUG=0`. Both reported the same Git revision.

- The daemon survived launcher exit and an abandoned HTTP connection.
  Repeated start returned instance `309882a1-e9ea-457d-a4cf-32aafc8ad6bc`, PID 38218.
- Four concurrent starts returned instance `6ebdad55-21e0-41c8-926e-7bd8ca937fd2`, PID 38305.
  A second Worktree on another port could not claim the same file through
  a path alias. Recovery succeeded after stop and after the test killed PID 38305.
- An HTTP 408 left the simulated reconnect busy. Stop and restart refused.
  The competing Worktree could not take the lock during the reconnect gap.
  After the reconnect, stop waited for process exit and HTTP became unreachable.
- The suite checked an occupied port, an unrelated live PID in stale metadata,
  a missing service, an initialization failure, and a readiness timeout.
  Foreground `serve` resolved relative overrides and exited on SIGINT.
  Status remained available from the Worktree with a missing root override.
- Build A kept CDHash `eca8617f635d9a5e7c7552d57724e979711f693e` and PID 38326
  during a failed compilation and after build B replaced the executable path.
  Build B refused a mismatched local write. Its explicit restart started
  PID 38337 with CDHash `5eef70bfd63ccd646d6bd41539fe9c1c9b9ef406`.
- The production daemon holds a host-wide lock across automatic DUT selection
  and reconnect. The fixture used an OS lock on a temporary file and a simulated
  port close and reopen. Physical USB ownership, reconnect, and release still
  need hardware verification.

## HTTP compatibility

- The final daemon preserved all 22 baseline route and method pairs. The two
  process control routes are private to the Unix socket. TCP requests to the
  former MCP path and the stop route returned 404.
- `python3 xpost-agent/tests/cli_http.py <release-agent>` passed 26 independent
  request and response cases for methods, paths, and typed fields. Business
  failure, missing `ok`, invalid JSON, HTTP failure, redirect, and connection
  failure produced nonzero exits.
- The fixture daemon exercised the baseline liveness and idle envelopes plus
  Map JSON and Perf framing. The musl test exercised the real TR3000
  `AgentClient` against separate fixed HTTP requests and responses.
- No live service was cut over. No USB operation, flash, database write,
  or formal experiment ran.

## Review and integration

The local Spec and Standards review checked the route table, the request
admission guard, Worktree isolation, process identity, and the final diff.
The review found a status failure with a missing root override and a possible
race with status probes that briefly take the instance lock. The final build
checked the status fix and retried transient lock contention at launch.
Automatic approval blocked the external review because it would disclose
the private taskbook and diff. No external review result exists.

[PR #23](https://github.com/nan-mu/xpost/pull/23) was open at `9e73d84` with
base `agent/rbpf-vm`. Its Release integration and offline `preflight`, HTTP
`/v1/preflight/medium` and `/v1/preflight/xdp/{name}`, and
`/v1/perf/{prepare,arm,freeze,read,release}` were absent from the baseline.
Their structured flash identity, preflight, epoch, boot ID, offset, and
digest fields need a CLI mapping when those branches integrate.
