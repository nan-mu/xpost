# PostgreSQL runtime configuration evidence

## TR3000 baseline

The maintainer tested the NAS connection from TR3000 on 2026-11-27 (UTC+8).
The test used ImmortalWrt 24.10.6 and the manually configured `/root/.db`.
It tested psql independently of the runner.

The maintainer returned one identity row with database `experiments` and role `experiment_rw`.
The server reported `172.16.1.3:5432`.
The maintainer did not report the final command or exit code.
The row matches the proposed identity SELECT.

Reuse this result for PostgreSQL connectivity and basic SQL execution from TR3000.
Application credential loading, schema readiness, privilege checks and writes require separate evidence.
The [TR3000 connection record](https://gitea.nas.nan-mu.cc/mcp/xpost/src/commit/721cbccaa74d8805c6e9a833fd2397449c32c162/tests/tr3000-db-connect.md#%E6%93%8D%E4%BD%9C%E4%B8%8E%E8%A7%82%E5%AF%9F) comes from Gitea branch `pr40`.

In this round, `ls -ldn /root/.db` on TR3000 exited 0 and reported a regular file owned by uid 0 with mode 0600.

## Runner and isolated database checks

- The focused settings test failed to compile before the runtime connector existed.
  It passed after the connector landed. The settings tests cover literal quoting,
  missing and invalid fields, file mode, and credential-free errors.
- `cd xpost-test && cargo test` passed 38 tests. Four PostgreSQL fixtures were
  ignored in that command and run separately in the disposable server.
- The fixture used PostgreSQL 18 and `sql/protocol_v1.sql`. The catalog returned
  132 tables. The fixture role used the documented table and schema grants.
- All four database fixture tests passed, including Case evidence, campaign
  analysis replacement, readiness, and EXB2 across HAL, AOT, JIT, and rBPF.
  A reconnect read the terminal EXB2 status. A constraint violation rolled back
  the status update and left no batch rows for that attempt.
- The standalone `db-preflight` binary read a synthetic root-owned `/root/.db`.
  It checked all 132 tables as the fixture role. Removing UPDATE on `bench.run`
  produced a specific missing privilege error and exit 1.
- The same binary accepted a quoted special-character password under SCRAM.
  An incorrect double-quoted password produced an authentication error without
  printing the synthetic credential. A missing file produced exit 1.
- The `all-plan` binary exited 0 without `/root/.db`.
  The release binaries used the real eBPF object. A binary scan found no legacy
  configuration keys or DSN template. The scan used only generic markers.
- The Docker toolchain resolver, rustfmt checks on changed Rust files, and
  `git diff --check` passed.
