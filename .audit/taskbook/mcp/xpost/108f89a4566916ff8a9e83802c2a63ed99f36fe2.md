## Regression in disposable PostgreSQL 18

The main agent created `reconcile_fixture` with a synthetic writer and the `release` schema.
The writer owned that schema and lacked database-level CREATE.
The fixture installed the observed default SELECT grants for both read-only roles.
The tests used no real credentials, NAS connection, or hardware.

The added test called the production `prepare`, `check`, and `resume` methods.
On the baseline, `check` and `resume` accepted three incompatible constraint changes.
They also accepted an active BEFORE INSERT trigger that replaced the Artifact media type.
On that baseline, `prepare` also accepted the trigger.

| Criterion | Final observation |
| --- | --- |
| Compatible schema and data | Preparation, check, and resume accepted a non-unique index and a renamed canonical trigger. The test inserted and read the original Artifact media type. |
| Missing integrity constraints | Check and resume reported the missing byte-length CHECK, composite primary key, and Artifact foreign key. The dropped constraints stayed absent across read-only calls. The table OID and the original row stayed intact. |
| Active write trigger | Preparation, check, and resume reported the target table and trigger. They preserved the object and row. All three entry points accepted the extra trigger after the fixture disabled it. |
| Preparation with a missing CHECK | Preparation refused the table and did not restore the CHECK automatically. |

The read-only validator checks primary and foreign key definitions. It checks the column sets of CHECK constraints.
It does not compare CHECK formulas. Catalog reads run in a repeatable-read, read-only transaction.
Preparation uses the same validator before commit.

## Build and database coverage

- `cargo test` in `xpost-test` passed 38 regular tests.
- Six ignored fixtures passed when run explicitly with synthetic `XPOST_CASE_TEST_DB_FILE`.
  They covered schema reconciliation and locks, network writer recovery, the new regression, Case, four-mode EXB2, and campaign analysis replacement.
- The first fixture order ran EXB2 before the network test.
  EXB2's retained rows prevented the network test's positive HAL snapshot rebuild.
  PostgreSQL rejected the FK restoration as designed.
  A fresh database ran the network test before EXB2. All six fixtures passed.
- `cargo build --release`, changed-file rustfmt, documentation lint, and `git diff --check` passed.
  The eBPF linker reported an LLVM shared-library warning. The release build completed.
